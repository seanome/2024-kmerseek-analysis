## How this started

`prostt5Search` was OOM-killed on Sherlock. Chasing that turned into a chain of six
distinct failures, each one hidden behind the previous. The pipeline now runs end to end:
the mini set completed 102 tasks in 7m19s with every arm green.

## What was wrong, in the order it surfaced

1. **Titin through ProstT5.** ProstT5 is a 3B-parameter T5 encoder run over each sequence
   whole, so peak memory scales with L² times concurrent threads. The human query FASTA
   leads with Q8WZ42 (titin, 34,350 aa). Fixed with `params.prostt5_max_len` (6000),
   filtering both query and target sides and publishing a skipped list.
2. **The `mini` profile had never applied on Sherlock.** Nextflow merges profiles in the
   order they are **declared in nextflow.config**, not the order passed to `-profile`.
   Verified on an isolated config: `sherlock,mini` and `mini,sherlock` produce
   byte-identical output. `mini` sat above `sherlock`, so every override lost silently —
   `make run-mini` had been requesting 16 cpus / 64 GB for a 200-protein test set.
3. **foldseek launders OOM into exit 1.** `easy-search` is a shell wrapper; when its
   `createdb` child is SIGKILLed it catches the signal, prints `Error: query createdb died`
   and exits 1. Nextflow sees a script error, so signal-based retry never fires. The script
   now greps stderr for the kill and re-raises 137.
4. **ProstT5's memory floor is the model, not the data.** The `mini` profile's 16 GB
   override killed a 194-sequence run just as dead as the uncapped full one. `mini` no
   longer overrides `prostt5_memory`.
5. **mksquashfs OOM on the login node.** It sizes its cache off total node RAM rather than
   the cgroup it is confined to. `prefetch-images` now converts inside `srun` with
   `APPTAINER_TMPDIR` on `$SCRATCH`.
6. **ProstT5 weights are tied to the foldseek release.** After the 9 → 10 bump, createdb
   rejected weights fetched by 9. `prostt5-weights` now moves the old dir aside first.

## Design changes made

**Every database is built once.** Four arms rebuilt the human *query* database inside every
task while caching only targets. `hhblitsBuildDB` already did it right; that pattern is now
applied to `prostt5Db`, `foldseekDb`, `mmseqsDb`, `mmseqsDomainDb`, and `reseekConvert`
(human mixed into its channel). ProstT5 was the expensive one: **90,236,496 of the arm's
173,017,199 residues — 52% — were re-encoding human nine times.**

Each `*Db` process emits a **single directory** under `storeDir` with the label recovered
from the directory name. `storeDir` forbids a tuple output, and a directory output alongside
a second output is what caused the recurring "Directory not empty" failures elsewhere in
this repo.

**foldseek 9.427df8a → 10.941cd33**, both arms. 9 has no `--gpu` flag at all. User chose
both arms over pinning v10 for ProstT5 only, accepting that **foldseekSearch results
collected on v9 are not comparable and that arm needs rerunning.**

**ProstT5 on GPU.** `--gpu 1`, with `--gres=gpu:1` and `--nv` in the sherlock profile.
`hns` has `gpu:4` so it stays on the condo partition. Confirmed working — `Use GPU 1`
accepted, createdb ran. GPU for the *search* stages sits behind `--gpu_search` (default
false): both binaries advertise `--gpu` but want a padded DB layout this pipeline does not
build. **Untested.**

**`scoreDomainCalls` memory from input file size.** Was a flat 96 GB via `label 'python'`;
a full run is ~10,179 such tasks, a 5.8 TB standing ask at `maxForks 60`. Now sized from
the regions file (8 GB base + 120 MB per compressed MB, capped at 96 GB). This required
giving it its own `python_scoring` label — **config directives beat script-declared ones**,
so the `python` label's flat memory was silently overriding any `memory {}` closure.

**`params.db_cache`** (default `outdir`) holds the target-side storeDirs, so the midi run
and the full run share databases built from identical target files.

**Midi run added** (`make run-midi`): human chr6 genes as queries, full proteomes as
targets. `make_mini_testset.py` gained `--gene-set chr6` and `--full-targets`. This
subsumes the old Mac-only 25-gene MHC vignette.

**Structures download on the login node** (`3b501e2`). `fetch-structures` pointed at a
Nextflow path that runs on compute nodes, which have no outbound internet. The login node
has the fast link, so EBI → Sherlock beats EBI → Mac → rsync → Sherlock.
`fetch-structures-login` was also missing the `write_structure_lists.py` step, so chicken
and ciona (fetched accession-by-accession, not in AFDB's proteome set) silently came up
empty.

**Rejected deliberately: sharing kmerseek's index across species.** Indexing human once and
searching 9 species against it would cut 3,312 index builds to 368, but kmerseek computes
regions on the **query** side. Making human the target moves the scored interval onto the
species protein. User: *"I want to see if the tool found titin's Ig domain, not what the
mouse region looks like."* Rationale is in the `kmerseekIndexAndSearch` docstring.

## Numbers established (all measured, not estimated)

**Titin Q8WZ42** — 34,350 aa, 307 Pfam domain instances across 6 families (162 PF07679
Ig I-set, 132 PF00041 fn3). 300 of 307 start past residue 1400.

**ProstT5 cap cost on the full human proteome:**

| cap | proteins dropped | domain instances lost |
|---|---|---|
| 4000 | 79 | 1,967 (3.9%) |
| 6000 (current) | 11 | 664 (1.3%) |
| 8000 | 4 | 347 (0.7%) |

**The structure arms have a bigger blind spot than the ProstT5 cap.**
`fetch_alphafold_structures.sh:153` keeps AFDB fragment F1 only (deliberately — fragment
coordinates don't map onto the full sequence), and AFDB ships full-length models only up to
2700 aa. 202 human proteins exceed that, carrying 3,469 instances (6.9%); **2,270 instances
(4.5% of all 50,185) start past residue 1400 and are invisible to foldseek/reseek/folddisco.
This is currently unrecorded anywhere** — unlike ProstT5's published skipped list.

**Titin reachability by target** (why the mini set cannot test the titin claim):
mouse 307/307, chicken/zebrafish/ciona 296, fly/worm 295, arabidopsis 1, **yeast 1,
E. coli 0**. 294 of titin's 307 domains are Ig/fn3, metazoan-only.

**chr6 midi query set:** 964 proteins, 2,358 of 50,185 domain instances (4.7%), 1,086
families, 1,073 of them present in mouse.

**Full run scale:** 3,312 `kmerseekIndexAndSearch` + ~10,179 `scoreDomainCalls` + ~121
baselines ≈ 13,600 SLURM jobs at `maxForks 60`.
